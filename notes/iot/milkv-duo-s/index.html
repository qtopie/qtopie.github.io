Milk-V Duo S 开发指南

June 20, 2026

本指南汇总了 Milk-V Duo S (基于 SG2000 主控芯片) 的硬件特性、系统烧录、基本配置及参考资源，帮助你快速上手开发。

1. 产品概述与硬件对比 (Overview)

Milk-V Duo S 是 Duo 系列的全面升级型号，升级了 SG2000 主控芯片，拥有 512MB 内存和更丰富的外部接口。其主要特性包括：

  • 双核/双架构启动：支持 RISC-V 核心 (C906@1Ghz + C906@700MHz) 或 ARM 核心 (Cortex-A53@1GHz)（通过硬件拨码开关切换，不能同时运行）。
  • 多媒体与视觉：支持双路摄像头输入 (2x MIPI CSI 2-lane 5M@30fps) 以及 MIPI DSI 视频输出 (4-lane)。
  • 网络与无线：板载 100Mbps RJ45 以太网口（支持配合 PoE HAT 使用 PoE），可选板载 WI-FI 6 / BT 5。
  • 存储与接口：板载 MicroSD 卡槽和 eMMC 贴片焊盘，配备 USB 2.0 Type-A HOST 接口与 Type-C 接口（可通过指令切换）。

2. 开发板接口与引脚分配 (Pinout)

Duo S 的 GPIO 逻辑电平在不同的排针上有所不同：

  • 排针 J3：GPIO 使用 3.3V 逻辑电平。
  • 排针 J4：GPIO 使用 1.8V 逻辑电平。

[!WARNING] 请注意连接外设时的电压匹配，防止损坏芯片。

3. 系统镜像下载与烧录 (Flashing OS)

系统可以通过 MicroSD 卡启动，也可以在 eMMC 版本上烧录启动。以下是常规的 MicroSD 卡启动 步骤：

1. 准备工作

  • Milk-V Duo S 开发板。
  • 1张容量大于 1GB 的 MicroSD 卡。
  • 电脑与 USB Type-C 数据线。
  • 镜像烧录工具，推荐使用 balenaEtcher 或 Rufus。

2. 下载系统镜像

从最新的 GitHub duo-buildroot-sdk-v2 Releases 下载适用于 Duo S 的系统固件镜像（例如以 milkv-duos- 开头的 .img.zip 压缩包）。

3. 烧录镜像

  1. 将 MicroSD 卡插入电脑的读卡器。
  2. 打开 balenaEtcher。
  3. 点击 Flash from file 选择刚才下载 of 系统镜像。
  4. 点击 Select target 选择你的 MicroSD 卡。
  5. 点击 Flash! 开始写入。写入并校验完成后，拔出 MicroSD 卡并插入 Duo S 的卡槽中。

4. eMMC 版本固件烧录 (USB Download)

eMMC 版本出厂未烧录固件，需要通过 PC 的 USB 接口烧录。官方提供 Windows 命令行烧录工具 CviBurn_v2.0_cli_windows（usb_dl.exe），Linux 下同样支持——SDK 中自带了 Linux 版的烧录工具。

[!NOTE] eMMC 固件版本需为 V1.1.3 或更新版本才支持 USB 烧录。

4.1 准备工作

  • 下载 eMMC 固件（如 milkv-duos-musl-riscv64-emmc_v2.0.1.zip），解压后得到：
    boot.emmc
fip.bin
rootfs_ext4.emmc
partition_emmc.xml
  • 若从源码编译 SDK，烧录工具位于：
    duo-buildroot-sdk-v2/build/tools/common/usb_dl/Linux/usb_dl
duo-buildroot-sdk-v2/build/tools/common/usb_dl/Linux/cv_dl_magic.bin
    （该目录下同时提供 Windows 版 usb_dl.exe）

4.2 Linux 烧录命令

Windows 与 Linux 命令几乎一致，唯一区别是芯片参数：

# Windows:  usb_dl.exe -s linux -c cv181x -i .\rom
# Linux:
./usb_dl -s linux -c 181x -i /path/to/rom
  • -c 181x：SG2000 系列芯片（Windows 版为 cv181x）
  • -s linux：操作系统类型
  • -i <dir>：固件所在目录（-i 直接指向包含上述 4 个固件文件的目录）

4.3 操作步骤

  1. 拔下 SD 卡（若有），按住开发板上的 recovery 按键。
  2. 用 Type-C 数据线连接 Duo S 与电脑。
  3. 松开 recovery 按键，开发板上电并进入烧录模式，终端实时显示烧录进度：
    [INFO] Waiting for USB device connection: ---
[INFO] found usb device vid=0x3346 pid=0x1000
[INFO] downloading file: ./rom/boot.emmc
[INFO] CVI_USB_PROGRAM
[INFO] updated size: 3384664/213100824(1%)
...
[INFO] USB download complete
  4. 烧录完成后开发板自动重启，蓝色 LED 闪烁即表示系统正常启动。

4.4 常见问题

  • USB 权限不足：设备 VID/PID 为 3346:1000。若普通用户无权限访问，可用 sudo 运行，或添加 udev 规则：
    SUBSYSTEM=="usb", ATTR{idVendor}=="3346", ATTR{idProduct}=="1000", MODE="0666"
  • 工具报错：Linux 版芯片参数需用 181x（不要带 cv 前缀），否则报 please specify choose chip among 180x, 181x, 182x, 183x。
  • 依赖：Linux 版 usb_dl 为静态链接 x86-64 ELF，无需额外安装 libusb 等依赖。

5. 网络连接与首开机配置 (Initial Setup)

1. 开机引导

  • 使用 Type-C 数据线将 Duo S 连接到电脑的 USB 口，或使用 5V 适配器供电。
  • 上电后，板载的蓝色 LED 将会开始闪烁。

[!TIP] 如果上电后蓝色 LED 没有闪烁，说明系统没有正常运行，这通常是由于 MicroSD 卡烧录错误或读写故障引起的，请尝试重新格式化并再次烧录。

2. 登录系统 (SSH via CDC-NCM)

默认情况下，Duo S 的官方镜像开启了 CDC-NCM USB 网卡功能：

  1. 使用网线连接板载网口，或者通过 Type-C 数据线将开发板的虚拟网口映射到电脑中。
  2. 电脑会自动识别出一个虚拟以太网卡，其默认网段 IP 地址为 192.168.42.1。
  3. 在电脑终端运行以下命令通过 SSH 登录开发板：
    ssh root@192.168.42.1
  4. 系统的默认密码为：milkv

3. 关闭蓝色 LED 闪烁 (可选)

如果不希望蓝色 LED 持续闪烁，可以在开发板登录后运行以下指令将其关闭：

mv /mnt/system/blink.sh /mnt/system/blink.sh_backup && sync
# 重启后 LED 将不再闪烁
reboot

6. 自定义镜像构建 (Custom Image Build)

记录于 2026-08-10。使用 duo-buildroot-sdk-v2 在 Linux (Ubuntu 24.04) 上完整构建自定义 eMMC 镜像。

6.1 启用特性

通过修改板级内核 defconfig 启用了以下功能：

  • eBPF：CONFIG_BPF=y, CONFIG_BPF_SYSCALL=y, CONFIG_BPF_JIT=y（含 CONFIG_BPF_JIT_ALWAYS_ON）
  • iptables：CONFIG_NETFILTER=y, CONFIG_NETFILTER_XTABLES=y, CONFIG_IP_NF_FILTER=y, CONFIG_NF_TABLES=y, CONFIG_IP_NF_NAT=y
  • TUN：CONFIG_TUN=y（支持 TUN/TAP 虚拟网卡）
  • 蓝牙：CONFIG_BT=y + BREDR/LE/RFCOMM/BNEP/HIDP + HCIUART(H4)
  • CONFIG_NET_CORE=y, CONFIG_PACKET=y

内核版本：Linux 5.10（linux_5.10/），riscv64 musl。

6.2 构建命令

cd duo-buildroot-sdk-v2
source build/envsetup_milkv.sh milkv-duos-musl-riscv64-emmc
# 分阶段构建
build_uboot && build_kernel && build_ramboot && build_osdrv \
  && build_3rd_party && build_middleware && build_cvi_rtsp \
  && build_tpu_sdk && build_tdl_sdk && build_pqtool_server \
  && pack_cfg && pack_rootfs && pack_data && pack_system \
  && copy_tools && pack_upgrade

6.3 Ubuntu 24.04 构建问题修复

  • host-m4 1.4.19/1.4.20 编译失败（glibc 2.43 下 C23 语法冲突）→ 升级到 m4 1.4.21
  • dbus-glib 0.112 编译失败（C23 中 bool 成为关键字，局部变量 dbus_bool_t bool; 冲突）→ 打补丁将变量重命名为 bval
  • make_ext4fs 报 libpcre.so.3 找不到 → 需要设置 LD_LIBRARY_PATH 指向 Ubuntu-18.04 runtime 后再跑 pack_system/pack_upgrade：
    export LD_LIBRARY_PATH=~/.local/share/lutris/runtime/Ubuntu-18.04-x86_64
  • 慢速源下载卡住（sources.buildroot.net 等）→ 用 curl -C - 断点续传手动下载到 buildroot/dl/ 目录

6.4 产物

最终可烧录 zip（结构与官方 eMMC 固件一致，可用于 usb_dl 烧录或 OTA 升级）：

out/milkv-duos-musl-riscv64-emmc-custom-YYYYMMDD.zip
├── boot.emmc          (内核 + 启动镜像)
├── fip.bin
├── partition_emmc.xml
└── rootfs_ext4.emmc   (rootfs，含 iptables)

rootfs 已确认包含 iptables / libxtables（buildroot 包 BR2_PACKAGE_IPTABLES）。

6.5 SD 卡版本 (musl-riscv64-sd)

同样的特性配置也应用到了 SD 卡变体（milkv-duos-musl-riscv64-sd），构建完成后用 pack_sd_image 生成单个可烧录镜像：

out/milkv-duos-musl-riscv64-sd.img  (~941MB，MBR 分区)
├── 分区1: boot.vfat (fip.bin + boot.sd, 128MB)
└── 分区2: rootfs.ext4 (含 iptables/ip6tables)

用 Balena Etcher / dd 写入 microSD 卡即可启动。

[!NOTE] 注意：SD 变体打包阶段不需要 Ubuntu-18.04 runtime 的 LD_LIBRARY_PATH（pack_system/pack_cfg 对 sd 类型跳过，genimage 自行设置 libconfuse）。若全局设置了该变量会导致内核编译阶段 perl 报 XCRYPT_2.0 not found 错误。

6.6 eMMC 烧录实战记录（2026-08-10）

记录了在 Linux (Ubuntu 24.04) 下用 usb_dl 烧录 eMMC 固件的完整实战过程，包括一次自定义 fip.bin 烧录失败的排查经历。

6.6.1 烧录流程回顾

  1. 解压固件到目录（boot.emmc / fip.bin / partition_emmc.xml / rootfs_ext4.emmc / logo.jpg），确保 logo.jpg 存在（MISC 分区引用它，缺失会导致烧录中止）。
  2. 先启动烧录工具 再插入设备（烧录模式窗口约 10 秒）：
    ./usb_dl -s linux -c 181x -i /path/to/rom/

    ⚠️ 若先插设备再启动工具，容易错过 10 秒的 ROM 模式窗口，设备会回退启动系统（PID 变为 100c NCM）。

  3. 按住 recovery 键 插入 Type-C，烧录工具捕获设备（3346:1000）后自动开始。
  4. 观察进度直至 [INFO] USB download complete。
  5. 设备自动重启，用 ping 192.168.42.1（NCM 默认网关）或 SSH root@192.168.42.1（默认密码 milkv）确认启动成功。

6.6.2 判断设备当前处于什么模式

PID含义特征
3346:1000ROM 烧录模式usb_dl 可捕获，需按住 recovery 进入
3346:100cNCM 正常系统枚举为 Cvitek NCM，ping 192.168.42.1 通

内核日志确认设备状态最可靠（journalctl -k | grep "usb 3-4"，注意可能受 apparmor 干扰 lsusb）。

6.6.3 排查：自定义 fip.bin 烧录失败

现象：自定义固件烧录时，fip.bin 每次都能完整传输（日志 send fip.bin finish），但设备随后不切换到第二阶段，而是重新以 PID 1000 枚举，usb_dl 陷入 set MGN1 flag 空转循环。

对照实验：改用官方 milkv-duos-emmc-v1.1.4.zip 固件，一次烧录成功（USB download complete），设备正常启动。结论：问题在自定义 fip.bin，而非硬件/USB 线/烧录流程。

fip.bin 对比（CVBL01 头格式，含 BL2 + lzma 压缩段 + OpenSBI）：

来源大小MD5
官方 v1.1.44249606aa8c5297955d937471b61ecbd9a3f42
自定义 SDK 构建4930565c281b590706973874c13569483d17c2

自定义 fip 明显偏大（+68KB），内部组件（BLCP/MONITOR/LOADER_2ND）组合与官方不同，导致 ROM 无法把控制权交给第二阶段引导。待办：核对 fsbl 构建时 LOADER_2ND_PATH（应指向 u-boot-2021.10/build/<project>/u-boot-raw.bin）、BLCP_2ND_PATH（RTOS cvirtos.bin）等组件参数。

6.6.4 经验教训

  • 烧录工具应先启动等待，再让设备进入烧录模式。
  • 烧录模式窗口短，可先确认设备已脱离系统（无 NCM 接口）。
  • 刷机遇到 fip 阶段反复失败的排查顺序：换官方固件对照 → 确认 fip 差异 → 检查 fsbl 打包参数。

3. 刷机命令（Linux）

# ① 解压固件，整理 rom 目录（usb_dl 需要 fip.bin / boot.emmc / rootfs_ext4.emmc / partition_emmc.xml）
unzip -o milkv-duos-musl-riscv64-emmc_2026-0810-2156.zip -d rom/

# ② 先启动烧录工具等待设备（Linux 用 181x，Windows 用 cv181x）
./usb_dl -s linux -c 181x -i rom/

# ③ 设备进入烧录模式：确认无 SD 卡 → 按住 recovery 键 → Type-C 插 PC → 松开
#    此时 lsusb 应显示: 3346:1000 CVITEK USB Com Port (ROM 烧录模式)
#    若显示 3346:100c 说明还在正常系统 (NCM 模式)

# ④ 等待烧录完成：日志出现 [INFO] USB download complete
#    设备自动重启，蓝色 LED 闪烁 = 启动成功

# ⑤ 验证
ping 192.168.42.1                              # 应通
ssh root@192.168.42.1                          # 密码 milkv

4. 烧录时序关键点

  • 先启动 usb_dl 再让设备进入烧录模式（窗口约 10 秒）
  • fip_tx_offset 分段传输 fip.bin（4096/38400/78336/… 逐步增长），最后 send fip.bin finish
  • fip 传输完成后，设备若能切换到第二阶段继续烧 boot.emmc → rootfs_ext4.emmc 即成功； 若重新枚举回 PID 1000 空转 set MGN1 flag = fip 不被 ROM 接受（develop 分支的失败特征）
  • logo.jpg 缺失仅警告不阻断（[WARN] unable to open /tmp/v201-rom/logo.jpg）
